# OpenAPI 接口增量变更清单（2026-10-16）

整理日期：2026-10-16。比较基线：`6f57de2`（v0.8.0）；OpenAPI 更新、映射同步及验证完成提交：`938f857`（`* feat: sync deliverable options and relation unlink APIs`）。

本文记录在 [ZenTao 22.7 OpenAPI 接口变更清单](./openapi-22.7.md) 之后的一次增量更新，依据仓库中的 `data/zentao-openapi.json`、`scripts/zentao-api-map.json`、生成注册库及测试结果整理。接口数量按 HTTP method + path 统计，响应 schema 的变化表示规范契约变化，不代表已通过真实服务确认。

路径均相对于 `/api.php/v2`。SDK action 在清单中记为 `模块-action`，调用时使用 `request('模块/action', params)`。

## 2. 新增接口与路径迁移

| HTTP 方法与路径 | SDK action | 主要入参 | 返回与用途 |
| --- | --- | --- | --- |
| `GET /projects/{projectID}/deliverable-options` | `deliverable-options`，新增 | 必填路径参数 `projectID: integer` | 提取 `deliverables` 对象，属性名为交付物定义 ID，值为名称；供创建项目交付物时选择定义，无分页 |
| `DELETE /relations/{relationID}` | `relation-unlink`，迁移 | 必填路径参数 `relationID: integer` | 返回含 `status` 的操作结果；删除指定自定义关联关系，SDK 沿用 `resultType: text` |

### 2.1 交付物候选定义

`deliverable-options` 的注册定义为：

```json
{
  "name": "options",
  "type": "get",
  "method": "get",
  "path": "/projects/{projectID}/deliverable-options",
  "resultType": "object",
  "resultGetter": "deliverables"
}
```

该接口返回 ID 与名称的映射对象，而 `deliverable-list` 返回已提交交付物的分页数组。两者语义不同，候选定义接口通过显式 `name` 和 `type` 映射生成独立 action，不进入 `deliverable-list` 的 scoped-list 合并流程，也不设置 `pagerGetter`。

```ts
const options = await request('deliverable/options', { projectID: 2 });
// options.data 为交付物定义 ID -> 名称的对象。

const submitted = await request('deliverable/list', {
  projectID: 2,
  browseType: 'normal',
});
// submitted.data 为已提交交付物数组，submitted.pager 为分页信息。
```

### 2.2 关联删除路径替换

旧路径已从本次 OpenAPI 规范中删除：

```text
DELETE /relations/{objectType}/{objectID}/{relatedObjectType}/{relatedObjectID}/{relationName}
```

新路径为：

```text
DELETE /relations/{relationID}
```

SDK 保留 `relation-unlink` 名称，将映射键迁移到新路径，并移除原来的五个路径参数。此变更不兼容旧调用参数；仅传原参数会因缺少 `relationID` 而失败。

`relationID` 来自 `relation-list` 响应的 `relations[].relationID`，归一化后位于 `response.data` 的各项中。只有 `relationType === 'custom'` 的自定义关系可以删除。`relationID` 是关系记录 ID，不能用关联对象 ID 或 `relationKey` 替代。

```ts
const relations = await request('relation/list', {
  objectType: 'story',
  objectID: 1,
});
// 从 relations.data 中选择要删除的自定义关系，读取它的 relationID。

await request('relation/unlink', { relationID: 8 });
```

示例中的编号仅用于演示调用方式。服务端是否仍兼容旧路径，本次未通过真实请求确认。

这 11 个字段虽然从 `parameters` 中删除，但各接口的 `browseType` 说明仍要求在搜索时传 `param`，或在查询未完成待办时传 `status=undone`。SDK 的查询组装逻辑只发送 action 声明的参数，直接按新规范生成会让这些字段丢失。

本次在 `scripts/zentao-api-map.json` 中为这 11 个接口显式保留完整 `params` 定义。生成后的参数名称、类型、默认值、选项、说明及结构化查询元数据均与比较基线一致。`my-testtasks` 使用 `browseType=bySearch`，其他九个搜索接口使用 `bysearch`，大小写保持原样。

```ts
await request('my/tasks', { browseType: 'bysearch', param: '12' });
await request('my/testtasks', { browseType: 'bySearch', param: '12' });
await request('my/todos', { browseType: 'undone', status: 'undone' });
```

`params` 映射采用整体覆盖语义。后续这些接口的其他查询参数发生变化时，也需要同步检查对应映射，避免旧覆盖遮蔽新规范。是否可以移除上述兼容字段，需要先核实服务端契约及规范说明。

### 3.2 交付物列表筛选选项（1 个）

调用方应按新说明检查筛选含义，尤其是 `normal`、`pending` 和 `submitbyme`；已有值没有从本次选项列表删除。

## 5. 映射、生成与覆盖审计

- 为 11 个 `my-*` 接口补入完整 `params` 覆盖，以保留兼容查询参数。
- 通过 `bun run scripts/update-registry.ts` 更新 `src/modules/generated.ts`；新增 action 同步进入 `BuiltinActionMeta`，返回类型为 `object`。
- 保持 `file-create` 的 `multipart/form-data` 和二进制文件字段，上传回归测试通过。
